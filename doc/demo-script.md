# 首期演示脚本（第 6 周末）

> 目标：管理员一次点击演示主数据管理平台六大能力——模型、编码、维护、审核、质量（分发为第 7 周预览）。
> 前置：后端（`ruoyi-admin`，端口 8080）+ Redis + MySQL `mdm` 库已初始化；前端 `npm run dev`。
> 演示账号：admin / admin123。

## 一、模型管理

1. 进入「主数据管理 → 模型管理」，左侧分类树选中根分类，点击「新建对象」。
2. 填写对象编码 + 名称：
   - 对象编码：`customer`，对象名称：**客户**
   - 配置属性（示例）：
     | 属性 | 编码 | 类型 | 必填 | 唯一 |
     |------|------|------|------|------|
     | 客户编码 | `cust_code` | VARCHAR | 是 | 是 |
     | 客户名称 | `cust_name` | VARCHAR | 是 | 否 |
     | 客户等级 | `cust_level` | VARCHAR | 否 | 否 |
     | 状态 | `status`（由平台内置） | | | |
     - `cust_level` 值域选「枚举」，值填 `A,B,C`。
3. 点击「发布」。系统动态创建 `mdm_data_customer` 表，对象状态变为**已发布**。

## 二、编码规则

1. 进入「编码规则」，选中 customer 对象，点击新增规则。
2. 配置分段：常量 `CUST-` + 日期 `yyyyMMdd` + 流水号（周期=日，位数 4）。
3. 编码字段选 `cust_code`，点击预览确认生成如 `CUST-20260821-0001`。
4. 保存。

## 三、数据维护（走进台式操作）

1. 进入「数据维护」，选择 customer 对象。
2. 点击**新增**，仅填写客户名称 `杭州示例制造有限公司`、等级 `A`，**不填客户编码**，提交。
   - 观察：`cust_code` 自动回填 平台编码方案生成的编码。（此时未开审核，直接生效）
3. 列表出现一条草稿数据，点击**生效**使其进入已生效状态。

## 四、审核流程（核心演示点）

1. 进入「审核 → 审核配置」，选择 customer 对象：
   - 打开「启用审核流程」开关，审核角色选 admin（保持默认即可），保存。
2. 回到「数据维护」：
   - **新增**一条客户，提交后提示「已提交审核，审核通过后生效」，列表**不出现**该数据。
   - **编辑**步骤三生成的已生效数据，改客户名称为 `杭州示例制造有限公司（华东）`，提交后同样提示待审核，原数据保持不变（演示 7.3：不覆盖生效数据）。
3. 进入「审核 → 审核任务」：
   - 默认展示待审核列表，两条任务（新增一条、修改一条）。
   - 点「查看」展开**变更前后快照对比**：修改任务显示 客户名称 从旧值变为新值。
   - 对修改任务演示**驳回**：填写原因「名称请按规范填写」，提交 → 任务变已驳回，原数据仍为旧值。
   - 对新增任务点「通过」→ 数据落库生效，列表出现该客户。
4. 回到数据维护，确认已生效数据为未驳回前的旧值（证明驳回不回写）。

## 五、数据质量

1. 进入「数据质量」，选择 customer 对象：
2. 「校验规则」Tab：新增一条规则，目标属性 `cust_name`，加密正则 `^[A-Z]`，提示「客户名称需以大写字母开头」，启用。
3. 「重复检测」Tab：查重字段选 `cust_name`，执行查重，演示分组结果。
4. 在数据维护重复录入相同名称 → 保存时平台提示重复/校验失败 → 到「质量台账」Tab 看到校验失败或重复记录，演示处理为「已处理 / 忽略」。

## 六、分发（第 7 周预览）

1. 进入「数据分发」，演示菜单入口已就绪；订阅方配置 / 推送记录 / Excel 导入导出将在第 7 周接入。

## 展示说明要点

- **不覆盖生效数据**：审核开启后，修改走待审核快照，通过才合并，驳回则原样保留——这是本周的核心交付。
- **快照对比**：审核任务「查看」直接展示变更前后字段级差异。
- **全链路**：一处对象从模型 → 编码 → 走审核的数据，任何环节演示一目了然。
