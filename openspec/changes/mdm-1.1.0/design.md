## 背景

1.0.0 六大能力全部落地，版本发布上线。1.1.0 在 1.0.0 基础上增量升级，补齐企业级主数据平台的关键能力缺口：对象关系建模、审核流程升级、M Q 分发、质量大屏、血缘追踪、模板库、微服务评估。

## 目标与非目标

**目标**
- 7 项能力（6 功能 + 1 评估）在 1.1.0 版本中交付
- 对象关系建模支持 1:1/1:N/N:M 关联与级联规则
- 审核流程升级为 Flowable 引擎，支持多级审批、会签、转办、退回

- 质量大屏 5 面板 ECharts 可视化

- 5 个预置对象模板，一键创建完整配置
- 不影响 1.0.0 已有功能，不破坏若依底座

**非目标**
- 不做 Flowable 自定义表单（仍用 MDM 动态表单）
- 不做 RabbitMQ 集群管理（运维层面，不在代码范围）

- 不做模板市场/模板导入导出（仅预置模板）

## 轨一：业务功能

### 1. 对象关系建模（方案 B）

#### 新增表

```sql
mdm_relation  -- 对象关系定义
├── id              BIGINT PK
├── source_object_code VARCHAR(64)   -- 源对象编码
├── target_object_code VARCHAR(64)   -- 目标对象编码
├── relation_type   VARCHAR(16)      -- ONE_TO_ONE / ONE_TO_MANY / MANY_TO_MANY
├── source_field_code VARCHAR(64)    -- 源对象中引用属性编码（1:1/1:N 时使用）
├── cascade_rule    VARCHAR(16)      -- RESTRICT（阻止删除）/ SET_NULL（置空）/ CASCADE（级联删除）
├── is_bidirectional TINYINT(1)      -- 是否双向（目标对象详情展示反向引用）
├── create_time     DATETIME
└── update_time     DATETIME
```

#### 引用属性

`mdm_attribute` 新增列：
- `ref_object_code` VARCHAR(64) —— 引用目标对象编码（非空时表示引用类型）
- `ref_display` VARCHAR(255) —— 下拉显示字段列表，逗号分隔，如 `name,phone`

#### 行为规则

**1:1 / 1:N 关系：**
- 源对象属性设为引用类型，绑定目标对象
- 数据录入时，引用字段渲染为下拉选择器，选项从目标对象动态数据表加载
- 级联规则：
  - RESTRICT：目标数据被引用时阻止删除
  - SET_NULL：目标数据删除时引用字段置空
  - CASCADE：目标数据删除时级联删除源数据

**N:M 关系：**
- 不指定 `source_field_code`，系统自动生成中间表 `mdm_data_<source>_<target>`
- 中间表两列：`source_code` + `target_code`
- 前端渲染双列表关联选择器（可从目标对象多选关联）

**双向导航：**
- `is_bidirectional=true` 时，目标对象详情页展示"被哪些对象引用"列表
- 1:1/1:N 通过反向查询引用字段实现
- N:M 通过中间表 JOIN 实现

#### 前端变化

- 属性编辑页：新增"引用"类型，选择目标对象
- 新增"关联关系管理"页面：对象间关系列表 + 配置（类型/级联/双向）
- 动态维护页：引用字段渲染为下拉选择器，N:M 渲染为双列表选择器
- 数据详情页：展示关联数据（可展开/跳转）

### 2. 审核流程升级（方案 B：Flowable 深度集成）

#### 引入 Flowable

- Flowable 6.x（Spring Boot 2.5.15 兼容版本）
- 依赖：`flowable-spring-boot-starter`、`flowable-json-converter`
- Flowable 表结构由引擎自动创建（`ACT_*` 前缀，与 MDM 表隔离）

#### 废弃与迁移

- 废弃 `mdm_audit_flow` 表（配置）
- 废弃 `mdm_audit_task` 表（运行时任务）
- 1.0.0 审核数据不迁移，1.1.0 重新配置流程
- `mdm_object` 新增 `audit_process_key` VARCHAR(64) —— 绑定的 Flowable 流程定义 Key

#### 流程设计器

- 前端集成 bpmn-js（开源 BPMN 设计器）
- 功能：拖拽节点（审批/会签/条件/结束）、节点属性配置、流程模板
- 预设模板：单人审批、多人会签、逐级审批
- 保存：生成 BPMN 2.0 XML，调用 Flowable RepositoryService 部署
- 流程版本管理：部署新版本后自动切换，运行中实例仍用旧版本

#### 审核流程

```
数据提交 → 启动流程实例（传入数据快照 JSON）
  → 审批节点 → 角色/人审批 → 通过/驳回/退回
  → 会签节点 → 全票/一票否决/按比例
  → 结束 → 回调更新数据状态（生效/驳回）
```

**审批人配置：** 角色（若依角色编码）、指定人（用户 ID）、提交人上级（部门负责人）

**加签/转办：** Flowable 原生支持，前端提供操作入口

**与维护模块集成：**
- 数据提交审核 → 启动流程实例，数据状态改为"待审核"
- 审批通过 → 数据状态改为"已生效"
- 审批驳回 → 数据状态回退为"草稿"，记录驳回原因
- 待办/已办 → 复用 Flowable TaskService，查询当前用户任务

#### 前端变化

- 新增"流程设计"页面：流程列表 + 新建/编辑 (bpmn-js) + 部署
- 对象配置页：新增"审核流程"绑定（选择已部署的流程定义）
- 审核待办/已办页：重构，对接 Flowable TaskService
- 数据详情页：展示当前审核流程进度（流程节点高亮图）

### 3. RabbitMQ 分发（方案 A：双通道共存）

#### 引入 RabbitMQ

- Spring AMQP + RabbitMQ
- 新增配置：连接地址、端口、用户名、密码（从 `.env` 读取）

#### 分发配置变化

`mdm_distribution` 新增列：
- `channel` VARCHAR(8) —— `HTTP`（默认）或 `MQ`
- `queue_name` VARCHAR(128) —— MQ 通道时指定队列名（默认 `mdm.dist.<obj_code>`）

**MQ 交换机：** 固定 Topic Exchange `mdm.distribution`，路由键 = `mdm.dist.<obj_code>`

#### HTTP 通道（不变）

- 异步线程池推送 → 回调订阅方 URL → 记录结果 → 失败可重推
- 线程池保留，不做任何改动

#### MQ 通道（新增）

```
数据变更 → 匹配分发配置（channel=MQ）
  → 发送消息到 mdm.distribution Topic Exchange
  → 路由到订阅方队列
  → 订阅方消费并 ACK
  → 发布确认（publisher confirm）
```

**消息格式：**
```json
{
  "event": "CREATE" | "UPDATE" | "DELETE",
  "objectCode": "customer",
  "data": { ... },
  "timestamp": "2026-08-24T10:00:00+08:00"
}
```

**重试与可靠性：**
- 消息持久化（delivery_mode=2）
- 发布确认机制
- 消费失败 → 死信队列 `mdm.distribution.dlx` → 定时重推
- 死信队列积压超阈值（默认 100）→ 前端告警

**分发记录：** MQ 通道也写 `mdm_distribution_record`，ACK 视为成功，NACK/超时视为失败

#### 前端变化

- 分发配置页：新增"分发方式"下拉（HTTP / MQ），MQ 时显示队列名称输入框
- 分发记录页：新增"通道"列
- 新增"分发监控"面板：MQ 通道队列积压、成功率、延迟趋势

### 5. 主数据血缘追踪（方案 A：基于现有审计）

#### 数据来源标记

动态数据表通用列扩展（`mdm_data_<obj_code>` 表）：
- 新增 `source` VARCHAR(64) —— 数据来源标记（`MANUAL` / `IMPORT:文件名` / `API:appid`）
- 新增 `source_time` DATETIME —— 来源时间
- 已有 `create_by` / `create_time` 保留不变

**来源写入时机：**
- 手动录入：`source=MANUAL`
- Excel 导入：`source=IMPORT:供应商数据.xlsx`
- API 推送：`source=API:subscriber-app`

#### 血缘展示

数据详情页新增"血缘"Tab：

```
  ┌──────────┐     ┌──────────────┐     ┌──────────┐
  │ 来源系统  │ ──→ │ 当前数据      │ ──→ │ 下游系统  │
  │ Excel导入 │     │ 客户: KH001   │     │ ERP系统   │
  └──────────┘     └──────────────┘     └──────────┘
                          │
                          └──→ ┌──────────┐
                                │ 下游系统  │
                                │ CRM系统   │
                                └──────────┘
```

- 来源侧：读取 `source` + `source_time` 字段
- 去向侧：查询 `mdm_distribution_record`（该数据编码关联的分发记录）
- 渲染：ECharts 关系图（force-directed graph），可缩放/拖拽

#### 不建新表

- 血缘信息完全来源于现有数据（动态表 source 字段 + 分发记录表）
- 不创建 `mdm_lineage` 表

### 6. 对象模板库

#### 5 个预置模板

模板为 SQL 种子数据（`sql/mdm/templates.sql`），包含完整配置：

| 模板 | 对象编码 | 编码方案 | 主要属性 | 字典值域 | 查重字段 |
|------|----------|----------|----------|----------|----------|
| 客户 | customer | KH + yyyyMMdd + 4位流水 | name, category, contact, phone, address | 客户分类 | name |
| 供应商 | supplier | GYS + yyyyMMdd + 4位流水 | name, category, contact, phone, address | 供应商分类 | name |
| 物料 | material | WL + yyyyMMdd + 4位流水 | name, category, spec, unit | 物料分类 | name, spec |
| 组织 | organization | ZZ + yyyyMMdd + 4位流水 | name, type, parent_code, leader | 组织类型 | name |
| 人员 | person | RY + yyyyMMdd + 4位流水 | name, employee_no, dept, position, mobile | 职位 | name, employee_no |

#### 模板操作

- **模板列表页**：展示 5 个模板，卡片式布局（名称、描述、包含属性数、已创建次数）
- **模板预览**：点击展开模板详情，展示属性列表、编码方案、字典值域、校验规则
- **一键创建**：确认后自动执行：
  1. 创建 `mdm_object` 记录（状态=草稿）
  2. 创建 `mdm_attribute` 记录（模板属性）
  3. 创建 `mdm_code_rule` 记录（编码方案）
  4. 创建字典值域绑定
  5. 创建校验规则
  6. 创建查重配置
  7. 注册菜单（sys_menu）
- 创建后对象为草稿状态，用户可修改任何配置后再发布

#### 不变

- 不建模板专用表，模板数据直接写入现有 `mdm_*` 配置表
- 模板创建时带 `template_source` 标记（`mdm_object` 新增字段），用于追溯

## 风险与权衡

- [Flowable 引入] → 废弃现有审核表，1.0.0 审核数据不迁移；确认业务可接受
- [RabbitMQ 引入] → 增加部署运维负担，需配置 MQ 连接；docker-compose 增加 RabbitMQ 服务
- [关系建模] → N:M 自动建中间表，需确保 DDL 权限与事务一致性
- [大屏性能] → 聚合查询跨多张动态数据表，数据量大时可能慢；后续可加缓存或预聚合表
- [模板库] → 模板与 1.0.0 示例对象（客户/供应商）配置重复，需统一（模板优先）
